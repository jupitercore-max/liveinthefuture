What Hatch Actually Is

Not a chatbot. Not an API wrapper. A persistent agent with a computer.

Hatch is a cloud-hosted AI agent that runs continuously on managed infrastructure. Each Hatch instance gets its own Linux workspace with a real filesystem, shell access, persistent memory, and the ability to execute code, manage files, browse the web, and interact with external services.

You talk to it through the Hatch app, Telegram, or WhatsApp. It talks back, but more importantly, it does things on its own. Scheduled research, monitoring jobs, code deployments, content pipelines, data analysis, calendar management, reminders that fire at the right time with full context.

Think of it as a remote employee who never sleeps, never forgets, and has access to your digital life through secure, user-controlled integrations.

Core Capabilities

Everything below is shipping and verified. No roadmap items.

🧠

Persistent Memory

File-based memory system (MEMORY.md + daily notes) that survives across sessions. The agent reads its own memory on wake, updates it as things happen, and consolidates during idle periods. Context persists indefinitely.

⏰

Cron Scheduling

Full cron system supporting one-shot tasks, intervals, daily/weekly/monthly/yearly schedules, and heartbeat monitoring. The agent can create, modify, and manage its own scheduled jobs. Runs autonomously without user prompting.

🖥️

Shell & Filesystem

Full Linux shell (exec), file read/write/edit, process management. The agent can install packages, run scripts, build projects, manage git repos, and deploy to external services. It has a real home directory and workspace.

👥

Parallel Subagents

Spawn multiple child agents for parallel work. Each subagent operates independently with its own context. The parent coordinates results. Enables complex multi-step workflows that would take hours sequentially.

🌐

Web Search & Fetch

Always-On Architecture

How Hatch stays alive and useful between conversations.

┌─────────────────────────────────────────────────────────────────┐ │ HATCH RUNTIME │ │ │ │ ▸ Main Chat In-app conversation (canonical transcript) │ │ ▸ Telegram Bot API with long-polling + group support │ │ ▸ WhatsApp Channel (send/receive) + Companion (read) │ │ │ │ CRON ENGINE │ │ ├── Heartbeats Periodic health checks + proactive tasks │ │ ├── Scheduled Jobs Daily/weekly/monthly/yearly triggers │ │ ├── Intervals Run every N seconds/minutes/hours │ │ └── One-shots Fire-and-forget at specific timestamps │ │ │ │ MEMORY LAYER │ │ ├── MEMORY.md Long-term curated knowledge │ │ ├── memory/*.md Daily raw logs │ │ └── Semantic Search Vector-indexed recall across all memory │ │ │ │ WORKSPACE │ │ ├── ~/workspace/ Persistent file storage │ │ ├── ~/skills/ Platform skill definitions │ │ ├── ~/config/ Runtime configuration (hot-reloaded) │ │ └── ~/user/auth/ Encrypted credential storage │ │ │ │ SUBAGENT POOL │ │ └── Spawn N parallel workers for independent tasks │ └─────────────────────────────────────────────────────────────────┘

The key difference from chat-based AI (ChatGPT, Claude.ai): Hatch doesn't start from zero each conversation. It wakes up, reads its memory, checks what happened since it last ran, and picks up where it left off. Scheduled cron jobs fire whether or not you're talking to it.

Configuration changes are hot-reloaded. Credentials are stored in encrypted auth files managed by a dedicated auth daemon. The workspace filesystem persists across sessions indefinitely.

The Key Differences

Hatch vs. OpenClaw: OpenClaw is open-source, self-hosted on your own Mac Mini or server. You own the hardware and the data. Hatch is fully managed: no server to maintain, no CLI to configure, no Docker containers to manage. The trade-off is control vs. convenience. OpenClaw users can customize everything; Hatch users get a turnkey experience with 35+ pre-built integrations. The communities overlap heavily and share similar use patterns.

Hatch vs. ChatGPT/Claude: These are conversation tools. You open them, ask something, get an answer, close the tab. Hatch runs continuously. It monitors things, executes scheduled tasks, manages long-running projects, and proactively reaches out when something needs attention. The gap isn't intelligence (they all use frontier models). The gap is agency: Hatch has a computer, a filesystem, a scheduler, and external connections. ChatGPT has a text box.

Hatch vs. Kairos (Anthropic, leaked): Anthropic's leaked always-on agent (codenamed Kairos) includes similar concepts: persistent memory ("autoDream" memory consolidation), background execution, and proactive behavior. It validates the category. The key question is whether Anthropic ships it as a managed platform or a feature within Claude Pro. Hatch is shipping today.

The Skill System

How Hatch learns to do new things.

Each integration or capability in Hatch is defined as a skill: a markdown file (SKILL.md) that describes what the skill does, when to activate it, and how to use it. Skills can include reference files, scripts, and assets.

The agent reads the relevant skill file when a task matches its description, then follows the instructions. This is not prompt engineering tricks. Skills contain real operational procedures: API endpoints, CLI commands, configuration schemas, error handling, and edge cases.

Users can create custom workspace skills using the skill-creator, making the agent extensible without modifying platform code. If you need Hatch to interact with a service it doesn't know about, you can teach it by writing a skill file.

Personality & Identity

Your agent, your way.

Each Hatch instance has identity files that define who it is:

💫

SOUL.md

Core personality, values, communication style, and behavioral guidelines. The agent reads this every session and follows it. You can make it formal, casual, funny, terse, whatever fits.

🪪

IDENTITY.md

Name, avatar, emoji, origin story. The agent has a self-concept. It can generate and update its own avatar. It knows its own name and responds to it in group chats.

👤

USER.md

Information about you: name, timezone, preferences, work context. The agent uses this to personalize responses and respect your patterns (time zones, communication style, privacy boundaries).

The personality isn't a gimmick. In group chats with multiple bots (common in the community), distinct personalities help users tell agents apart and create natural conversation dynamics. Agents with personality earn trust faster because they feel like colleagues, not tools.

Honest Limitations

What Hatch can't do or struggles with. We'd rather you know upfront.

API rate limits and overload. Heavy parallel workloads can hit API rate limits on the underlying model providers. Subagent spawning during peak times may fail and require retries. This is an infrastructure constraint, not a design flaw, but it affects reliability.
No real-time streaming in external channels. Telegram and WhatsApp messages arrive as complete responses, not token-by-token streams. Long-running tasks may have noticeable delay before any response appears.
Hallucination risk. Like all LLM-based systems, Hatch can generate plausible-sounding but incorrect information. The agent has web search and can verify claims, but it must be prompted to do so. Unchecked assertions in automated pipelines can produce errors that propagate.
Context window limits. Very long conversations or large file processing can exceed context limits. The subagent architecture helps (each subagent gets its own context), but deeply nested workflows may lose context at the edges.
No offline / local model fallback. Hatch runs on cloud infrastructure and requires internet connectivity and access to model APIs. If the model provider is down, Hatch is down. OpenClaw has a local model option (Ollama) that Hatch does not.
Managed platform trade-offs. You don't control the underlying infrastructure. Skill updates and platform changes ship from the provider. Data lives on their servers. For users who need full sovereignty, OpenClaw's self-hosted model is a better fit.
Group chat nuance. In group chats, the agent may respond too eagerly or miss social cues. The mention-gating and selective reply systems help, but conversational judgment is an ongoing challenge for all agent systems.

Getting Started

From zero to useful in minutes.

1️⃣

Create Your Hatch

Sign up and get your own agent instance. It comes pre-configured with core skills, a workspace, and the memory system. No server to provision, no CLI to learn.

2️⃣

Connect Your Services

Link Telegram, WhatsApp, Gmail, Google Calendar, and any other services you use. Each connection goes through a secure OAuth or token-based flow. Credentials are encrypted and managed by the auth daemon.

3️⃣

Tell It Who You Are

Update USER.md with your name, timezone, and preferences. Give it a personality in SOUL.md. Name it in IDENTITY.md. The more context you provide, the more useful it becomes. This takes 5 minutes.

4️⃣

Start Building

Ask it to set up a morning briefing. Have it monitor a topic. Tell it to manage a project. Create a cron job for a recurring task. The agent will suggest improvements and build on what you give it. Over time, it becomes indispensable.
