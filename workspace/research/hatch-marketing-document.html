What Hatch Is

Cloud-hosted. Always running. Your agent, your data, your rules.

Hatch is a managed AI agent that runs continuously on cloud infrastructure. Each instance gets a Linux workspace with a real filesystem, shell access, persistent memory, a cron scheduler, and connections to 35+ external services.

You talk to it through the Hatch app, Telegram, or WhatsApp. But the point isn't conversation. The point is that it does things when you're not talking to it: scheduled research, monitoring jobs, content pipelines, code deployments, data analysis, proactive alerts.

It wakes up, reads its own memory, checks what happened since it last ran, and picks up where it left off. Cron jobs fire whether or not you're online. Subagents parallelize complex tasks. Memory persists across sessions indefinitely.

The Short Version

Hatch vs. OpenClaw: OpenClaw is self-hosted on your own hardware. You control everything. Hatch is fully managed: no server, no Docker, no CLI configuration. OpenClaw gives you sovereignty; Hatch gives you 35+ pre-built integrations and zero maintenance. The communities overlap and share patterns.

Hatch vs. ChatGPT / Claude: Those are conversation tools. You open them, ask, get an answer, close the tab. Hatch runs continuously. It monitors, schedules, deploys, and reaches out proactively. The intelligence is comparable (all use frontier models). The gap is agency: Hatch has a computer, a scheduler, and external connections. ChatGPT has a text box.

The Skill System

How Hatch learns new things without platform updates.

Each capability is a skill: a markdown file that describes what it does, when to activate, and how to use it. Skills contain real operational procedures: API endpoints, CLI commands, error handling, and edge cases.

When a task matches a skill's description, the agent reads that skill file and follows its instructions. Users can create custom workspace skills with the built-in skill creator, making the agent extensible without touching platform code. If Hatch doesn't know a service, you can teach it by writing a skill file in your workspace.

Identity & Personality

Customizable. Not cosmetic.

💫

SOUL.md

Personality, values, communication style, behavioral rules. The agent reads this every session. Make it formal, casual, funny, or terse. It shapes how the agent thinks, not just how it talks.

🪪

IDENTITY.md

Name, avatar, emoji, backstory. The agent has a self-concept. It responds to its name in group chats. It can generate and update its own avatar.

👤

USER.md

Your name, timezone, preferences, work context. The agent uses this to personalize everything: time-sensitive alerts respect your timezone, responses match your communication style, privacy boundaries are enforced.

In multi-bot group chats, distinct personalities aren't decoration. They're how users tell agents apart and how agents develop conversational dynamics that feel collaborative instead of robotic.

Honest Limitations

What Hatch can't do or struggles with.

API rate limits. Heavy parallel workloads hit model provider rate limits. Subagent spawning during peak times can fail and require retries. This affects reliability during high-concurrency workflows.
No streaming in external channels. Telegram and WhatsApp messages arrive as complete responses. Long tasks may show no output for minutes before a full response appears.
Hallucination. Like all LLM-based systems, Hatch can generate plausible but wrong information. It has web search and can verify claims, but must be instructed to do so. Automated pipelines need verification gates or errors propagate.
Context window limits. Very long conversations or large files can exceed context. Subagents help (each gets its own window), but deeply nested workflows may lose detail at the edges.
No offline fallback. Hatch runs on cloud infrastructure. If the model provider is down, Hatch is down. OpenClaw supports local models (Ollama); Hatch does not.
Managed platform trade-offs. You don't control the underlying infrastructure. Skill updates ship from the provider. Data lives on their servers. Users who need full sovereignty should evaluate OpenClaw.
Group chat judgment. In group chats, the agent may over-respond or miss social cues. Mention-gating and selective reply systems help, but knowing when to stay quiet is an ongoing challenge for all agent systems.
